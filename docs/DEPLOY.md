# Deploying on Render

Everything is described in `render.yaml` (a Render Blueprint). Models run on the Hugging Face
router with the team's `HF_TOKEN`; nothing heavy (torch, OCR libraries) runs on Render.

| Service | Render type | Plan | What it is |
|---|---|---|---|
| `cosmetic-scanner-web` | Static site | free | The app (Expo web build of `frontend/`) |
| `cosmetic-scanner-n8n` | Web service (Docker, `deploy/n8n/`) | starter ($7) | n8n with the project workflow imported and published at every start |
| `cosmetic-scanner-api` | Web service (Docker, `Dockerfile`) | free | FastAPI: ingestion, OCR, agents, report, validator |
| `cosmetic-scanner-db` | Postgres | free (expires after 30 days) | n8n's database |

Hugging Face router (`HF_TOKEN`): `Qwen/Qwen2.5-7B-Instruct:featherless-ai` for the agents,
`Qwen/Qwen3-VL-30B-A3B-Instruct` for label OCR, `BAAI/bge-small-en-v1.5` embeddings for RAG.

## Request path

```
app (static site or Expo Go)
  -> POST https://cosmetic-scanner-n8n.onrender.com/webhook/cosmetic-scanner-live   header X-API-Key: EXPO_PUBLIC_WEBHOOK_KEY
  -> n8n calls https://cosmetic-scanner-api.onrender.com/...                          header X-API-Key: SCANNER_API_KEY
  -> the API calls the Hugging Face router                                             Authorization: Bearer HF_TOKEN
```

The services use their public https URLs: free Render services cannot receive private-network traffic.

## Keys

| Variable | Generated by | Used by | Secret? |
|---|---|---|---|
| `HF_TOKEN` | you paste it once | api | yes: never commit, never post |
| `SCANNER_API_KEY` | Render (`generateValue`) | api, n8n | yes |
| `EXPO_PUBLIC_WEBHOOK_KEY` | Render (`generateValue`) | n8n, web app | no: it is inside the public web app; it only stops casual misuse |
| `N8N_ENCRYPTION_KEY` | Render (`generateValue`) | n8n | yes: never change it after the first deploy |

## First deploy

1. Push the branch to GitHub.
2. Render dashboard: **New > Blueprint**, pick the repository and branch. Render reads `render.yaml`.
3. When asked, paste the team `HF_TOKEN`. Create the Blueprint.
4. Wait for the four resources. Check the real URLs in the dashboard: if Render added a suffix
   (e.g. `cosmetic-scanner-api-x1y2.onrender.com`), set:
   - n8n `SCANNER_API_URL` to the api URL,
   - web `EXPO_PUBLIC_SCAN_URL` to `<n8n URL>/webhook/cosmetic-scanner-live`, then redeploy the web site
     (Expo bakes it into the build).
5. Open the n8n URL once and create the owner account (first visit only).
6. Checks:
   - `https://<api>/health` returns `{"ok": true}`; any other API path without the key returns 401.
   - n8n logs show `importing ... (id ...)` and no publish warning.
   - The web app opens, and a scan with a known barcode reaches the report.

## Phones

Run the app with Expo Go pointing at the deployed n8n:
`frontend/.env` with `EXPO_PUBLIC_SCAN_URL=<n8n URL>/webhook/cosmetic-scanner-live` and
`EXPO_PUBLIC_WEBHOOK_KEY=<value from the Render env group>`, then `npm start` and scan the QR code.

## Things to know

- **Cold starts:** the free api sleeps after 15 minutes without traffic and needs about a minute to wake.
  Open the app a few minutes before a demo. n8n (starter) stays awake.
- **Postgres free** expires 30 days after creation (enough for the course). n8n stores its workflows
  there, but they are re-imported from git at every start anyway.
- **Changing the workflow:** edit it in n8n, export it with `scripts/export_workflow.sh` into
  `deploy/n8n/workflows/`, commit. The next deploy imports it.
- **RAG index:** the API loads `corpus/index/*.jsonl` into an in-memory Qdrant. After a corpus change,
  rebuild it locally (`pip install -r requirements-dev.txt`, then `EMBEDDING_BACKEND=local python -m app.rag.index`)
  and commit the new files.

## Local copy of the deployment

`docker compose up -d --build` runs the same api and n8n images with Postgres (see `docker-compose.yml`).
Fill `.env` from `.env.example` first.
